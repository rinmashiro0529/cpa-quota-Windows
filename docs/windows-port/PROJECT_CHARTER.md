# 原生 Windows 完整移植启动企划书

版本 1.0 · 2026-11-25 · Asia/Shanghai

## 1. 意图分析与项目目标

用户需要把 CPA Quota iOS 变成可长期维护、可靠日用的原生 Windows 产品，并以本仓库的计划统一后续开发者与 agent 的执行方向。目标包含完整功能、已修复的可靠性规则、Windows 平台体验、数据安全及正式安装更新能力。

交付仓库为 [rinmashiro0529/cpa-quota-Windows](https://github.com/rinmashiro0529/cpa-quota-Windows)。源项目为 [cpa-quota-ios](https://github.com/rinmashiro0529/cpa-quota-ios)，固定基线见 [SOURCE_BASELINE](SOURCE_BASELINE.md)。本次交付仅初始化规划，不表示已有 Windows 程序。

### 成功结果

1. 五个原生工作区及其完整用户流程在 Windows 上可用。
2. iOS 的网络、状态、凭据、统计、聊天和监控不变量在新实现中有回归证据。
3. Chat 的复杂能力、外置附件、历史管理、续写、搜索、记忆、技能与静态 HTML 预览完整落地。
4. WidgetKit / ActivityKit / Keychain 等能力有可解释、可测试的 Windows 原生映射。
5. 用户可安装、连接、使用、升级和恢复数据；开发者可构建、测试、定位问题和继续演进。
6. 所有结论追溯到版本、测试和产物；没有证据的部分不称为完成。

## 2. 完整移植的可执行定义

完整是 [FEATURE_PARITY](FEATURE_PARITY.md) 中每一个功能都达到 verified 或 verified_platform_equivalent，并满足 [ACCEPTANCE](ACCEPTANCE.md) 的发布门禁。平台等价须记录保留的用户价值、操作、数据、生命周期和不同之处，不能只写一个替代控件名称。

以下不能作为完整版本：只有额度页；聊天仅能发消息；没有取消/恢复；远端监控只有本地定时器；有截图但无交互；只生成 exe 未验证安装升级；把未执行测试列为成功。

开发里程碑允许功能尚未齐全，但必须标注 internal_alpha 或 internal_beta。所有 P0/P1、required_for_full_release 项仍进入正式完整版；优先级只决定顺序，不提供删除范围的授权。

| 场景 | 用户期望 | 设计要求 |

## 4. 范围与边界

完整范围由功能矩阵控制，至少包含：

- 额度与账号清单、诊断、详情、筛选和渐进刷新。
- CAP 所有现有范围、模型统计、趋势/分组/费用/请求明细及可信度标签。
- 管理凭据、推理 key、搜索 key、监控 token 的独立生命周期。
- 当前实际协议路径、模型目录、推理档位、文本与图片、停止/编辑/重发/接续。
- 记忆、全局与会话指令、slash 技能、五个搜索 provider 和来源展示。
- 会话管理、搜索、持久化、外置附件、升级恢复、版本化导出/导入。
- 远端监控授权、租约、停止、容量、缓存和 Windows 投递。
- 原生系统集成、Windows Widgets provider、紧凑概览、通知、深链、托盘、访问性。受支持且宿主可用时必须实现原生 Widgets；紧凑概览用于宿主缺失或不可用环境，并明确显示降级能力，技术验证失败本身不能豁免完整发布门禁。
- 依赖与许可、诊断、签名、x64/ARM64、安装更新和复审。

配套服务继续采用 Go。Windows 客户端不内嵌整个 CPA，不实现上游 OAuth 登录、账号修改或额度重置。模型生成及监控控制具有副作用，不能把“只读额度”推广成整个产品无写入或无费用。

源码中存在但默认不可达的 Responses 路径，不自动扩展成首发必须新增的独立产品入口；其实际可达性和兼容行为由基线合同确认。未来新增平台、跨设备同步和任意工具执行通过独立范围变更处理。

## 5. 核心技术决策

C# / .NET 10 LTS / WinUI 3；SQLite + 外置附件；DPAPI CurrentUser 秘密存储；MSIX；Windows 11 受支持版本为正式系统基线，x64/ARM64 独立产物。详细理由和重开条件见 [DECISIONS](DECISIONS.md)。

原生意味着业务界面和交互使用 Windows UI 体系。严格隔离的 WebView2 仅用于现有任意 HTML 静态预览；不是整套产品前端。预览能力须保留而且经过恶意内容测试。

## 6. 产品质量顺序

可靠性和数据保全 → 完整功能 → 原生可用性与访问性 → 可安装升级 → 性能与视觉细节。各层同时进入最早相关任务，不能把测试或安全全部留到最后。

界面采用 Windows 原生布局和输入习惯，保留品牌识别。iOS 的玻璃效果、导航结构和后台执行时间不作为逐像素或逐 API 仿制要求。

## 8. 治理与停止条件

每个功能有 owner、任务、测试、证据。主要技术变更须更新 ADR，并同时修改依赖和验收，不默默改变模型、存储或语义。

“完善”定义为：完整范围已验收、无未解决发布阻塞缺陷、候选 SHA 的必需检查通过、真实平台与分发能力已验证、已知限制如实披露。覆盖率数字、代码行数、截图数量不能替代这些条件。

当前计划不承诺一个未经工程验证的完成日期。M0 后按真实吞吐、风险和外部依赖估算里程碑；不得用压缩范围制造“提前完成”。

## 9. 明确的外部依赖

- 真实 CPA/CAP 测试权限与受控数据。
- 签名/发布身份、更新源、ARM64 与最低支持系统测试环境。
- Windows 远程推送所需的应用身份与云端配置。
- iOS 历史导出需要源项目配套 PR；没有导出入口不能假定能读取 iOS 沙盒或 Keychain。
- 任何平台能力不可用时，记录具体原因与可运行替代，但“完整”等级按受影响能力门禁判断。

这些依赖先通过模拟、合同、构建和可审查配置准备充分；只有执行到真实服务或发布步骤时才处理必要的账户/权限条件。
